# AfterPush v1.0.0

AfterPush v1.0.0 is a single-operator platform engineering prototype for
traceable deployments. It combines a FastAPI/PostgreSQL control plane,
immutable deployment revisions and promotion, GitOps publication/recovery
workers, Helm, Argo CD, Kubernetes, Terraform, and GitHub Actions.

## Included

- Deployment intent, revision, promotion, publication claim, Git commit, and
  runtime-verification state are kept distinct and auditable.
- Publication has namespace/RBAC gates and recovery-aware GitOps worker paths;
  Argo CD renders Helm values from Git and performs desired-state
  reconciliation separately.
- Terraform roots separate shared ECR/OIDC assets, legacy ECS infrastructure,
  and the EKS lifecycle. CI validates them without Terraform apply/destroy.
- Terraform defaults EKS control-plane access to private. The live cluster
  was found with public access open to `0.0.0.0/0` and was destroyed; a future
  restore must verify the private endpoint and managed security groups.
  Legacy ALB defaults are internal/TLS-only, SNS alerts use a scoped KMS key,
  and the accepted public-node-subnet trade-off is explicitly limited to a
  temporary, single-operator portfolio scope.
- The previously running EKS demo was shut down with a fresh, state-backed
  23-resource destroy plan. Shared Terraform state, the S3 backend, GitHub
  OIDC delivery identity, and ECR recovery repositories were retained.
- PostgreSQL was gracefully stopped; encrypted snapshot
  `snap-04c0bf420fd3f6715` was completed and verified before its original
  volume was deleted.
- A reproducible local demo uses `afterpush_test` and temporary Git state only.
- `scripts/aws-env.sh` provides dry-run-first, state-backed status/start/stop/
  verify guidance for cost-aware AWS operation.

## Validation scope

The [final validation report](../final-validation.md) records local, static,
CI, and live shutdown evidence. The lifecycle tool is tested with local mocks
and was also used for the verified live teardown. No live restore or
snapshot-based PostgreSQL recovery was performed.

## Deliberate boundaries

This is not a production SaaS or a claim of a currently running AWS/EKS
deployment. Live shutdown is verified; live restoration, Kubernetes rollout,
Argo CD sync, remote GitOps publication, and production database migration
remain unverified. Any future live use requires explicit operator approval,
verified account/region/state ownership, private EKS API access, out-of-band
secrets, and the documented recovery procedure. The retained snapshot and
recovery storage may continue to incur AWS charges.
