# v1.0.0 draft release summary

AfterPush v1.0.0 is a single-operator platform engineering prototype for
traceable deployments. It combines a FastAPI/PostgreSQL control plane,
immutable deployment revisions and promotion, GitOps publication/recovery
workers, Helm, Argo CD, Kubernetes, Terraform, and GitHub Actions.

## Included

- Deployment intent, revision, promotion, publication claim, Git commit, and
  runtime-verification state are kept distinct and auditable.
- Publication has namespace/RBAC gates and recovery-aware GitOps worker paths;
  Argo CD renders Helm values from Git and performs desired-state
  reconciliation separately.
- Terraform roots separate shared ECR/OIDC assets, legacy ECS infrastructure,
  and the EKS lifecycle. CI validates them without Terraform apply/destroy.
- Default EKS control-plane access is private. Legacy ALB defaults are
  internal/TLS-only, SNS alerts use a scoped KMS key, and the accepted
  public-node-subnet trade-off is explicitly limited to a temporary,
  single-operator portfolio scope.
- A reproducible local demo uses `afterpush_test` and temporary Git state only.
- `scripts/aws-env.sh` provides dry-run-first, state-backed status/start/stop/
  verify guidance for cost-aware AWS operation.

## Validation scope

The final validation report records local, static, and CI evidence. The AWS
lifecycle tool is tested with local mocks; it does not prove a live restore.
Normal pull-request CI still needs to pass for the Milestone 5 branch before
this draft can become a GitHub release.

## Deliberate boundaries

This is not a production SaaS or a live AWS/EKS deployment claim. No live
Terraform apply/destroy, Kubernetes rollout, Argo CD sync, remote GitOps
publication, production database migration, tag, or GitHub Release is created
by this draft. Live use requires explicit operator approval, verified account/
region/state ownership, private EKS API access, out-of-band secrets, and the
documented recovery procedure.
